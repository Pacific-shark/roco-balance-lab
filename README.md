```sh
# Node.js 24+；不需要模型API Key或云数据库
pnpm install --frozen-lockfile
pnpm build
pnpm start
# 打开 http://127.0.0.1:4198
```

开发时先运行 `pnpm start` 启动本地API，再在另一终端运行 `pnpm dev`；4197端口代理API至4198。基础资料会从仓库固定快照首次导入 `.local/research.sqlite`。该文件保存实验与检查点，应自行备份；不会上传GitHub。

默认100局训练、60秒累计时限、3个候选，一次一个本地工作线程；任务可以暂停和继续，数据或执行代码版本变化会拒绝接续旧检查点。`pnpm test:workbench` 包含一项真实100局的有界原型集成测试。完整测试可用 `node --test --test-isolation=none test/*.test.mjs`。

**训练和评估本身不调用大模型API，API token为0；开发对话和设计生成不包含在这个数字里。** GitHub只保存源码、方案和固定公开资料；仍为私有，不自动公开部署或启动长训练。

## 可以操作什么

- 两支完整六人队伍：选择首发、出招、聚能、主动换人和力竭补位；独立生命与能量，初始四点魔力，聚能回复五点能量。
- 两个真实训练的策略模型：独立权重、带种子训练、历史与固定规则对手。浏览器本机训练，可下载模型，无大模型 API。
- 独立培养与搜索：种族值、六项资质、30 种性格共同决定面板；性格按用户确认的一项 +10%、另一项 −10%。每名成员筛选 600 组培养候选，再重训策略。可检查和修改每项面板。
- 团队支援回放：点击证据返回触发回合，区分效果所属的技能或特性、触发者和受益者。
- 团队机制调整：分别修改富养化的场下回能、盘根木的后台回血，或关闭养分重吸收。保持双方六人队伍，在相同策略与对手场景下比较。
- 全量资料检索：625 形态、579 技能、242 个特性名称（245 个内部 ID），保留学习条件和来源。

## 案例：同一次行动的收益应该记给谁

**富养化是技能；养分重吸收才是奇丽花的特性。** 前者耗能 3，主动为场下精灵回复能量；后者回合末回复自身能量。富养化作为草系技能，还能触发场下森巨人自己的盘根木回血。三者分别登记来源，不能把这些效果合并归因于奇丽花的特性。

这也决定了实验要保留技能槽、行动回合、实际能耗和收益溢出，不能给某只精灵无成本地加一项“团队支援能力”。

## 范围与结果

| 层 | 范围 | 用途 |
|---|---|---|
| 图鉴 | 2026-10-14 BWIKI 快照，625 形态 / 466 图鉴编号；311 技能池、30,921 条学习来源、54 条术语 | 查机制与学习条件 |
| 6v6 引擎 | 10 个形态、42 个注册技能、18 属性，4 组固定实验阵容 | 检验团队机制与策略学习 |
| 旧版 1v1 | S3 旧快照、6 只固定配招精灵 | 保留计算调试，不用于评价本游戏 PVP |

两个种子各预训练 1,000 场，完成 20,640 场培养筛选，再以选出的配置各重训 4,000 场。结果来自 public/team-models/：

| 种子 | 初始化对规则得分 | 训练后对规则得分 | 交叉对战上限平局率 | 平均主动换人 / 场 |
|---|---:|---:|---:|---:|
| 42 | 62.50% | 60.42% | 0% | 8.83 |
| 137 | 60.42% | 68.75% | 0% | 12.63 |

规则得分来自 48 个固定场景（胜 1、平 0.5、负 0）；交叉对战为 24 个场景。训练与评估阵容重叠，以上不是泛化测试或天梯胜率。两个模型使用公开启发式权重初始化，其已有能力不算学习收益。初次线性 Q 模型出现频繁换人，失败记录同样保留在 docs/evidence/team-q-v1-failure.json。

种子 42 的训练得分低于同配置初始化；种子 137 提升。因此当前不能宣称训练稳定提升，更不能称为求得最优打法。培养搜索只保证接受在指定参考场景中不劣于原方案的候选；没有证明全队联合最优，未搜索低资质控速或所有配招。

v0.2.1 当时未实现自动配队与配招搜索；v0.3.0 已在上述子集中加入有限搜索。全图鉴战斗、隐藏配置信息推断、愿力、首领化、天气和印记仍未实现。社区数值公式、同速、防御与离场结算尚未通过游戏录像校准。六人框架不等于全游戏复刻，不能据此认定某精灵或技能“超模”。

## 运行与复现

需要 Node.js 22.12+ 与 pnpm，推荐 Node.js 24。

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm test
pnpm build

# 从已保留的 BWIKI 快照和属性表重建团队数据
node scripts/build-team-data.mjs
# 独立搜索培养、重训，并生成评估与初始化对照
node scripts/optimize-team.mjs 42 4000
node scripts/optimize-team.mjs 137 4000
```

默认本地地址 http://127.0.0.1:4197/，静态构建位于 dist/。如运行环境限制 Node 测试子进程，可用 `node --test --test-isolation=none test/*.test.mjs`。

页面的机制对照沿用冻结策略；按调整规则重新训练是另一种实验。成对对照的 JSON 可下载。浏览器临时模型刷新后不保留，请先下载。
