# 洛克平衡实验室

一个面向游戏策划面试的研究原型：让两个 AI 通过强化学习自博弈学习行动，再检查特性、技能分配与打击面带来的收益，最后比较调整前后的结果。

[打开在线演示](https://pacific-shark.github.io/roco-balance-lab/)

**当前是训练流程原型，不能用于判断真实赛季的精灵强度。** 数据整理范围与模拟范围分别标注。项目与腾讯、魔方工作室及 BWIKI 均无隶属或官方合作关系。

## 可以实际操作什么

- 搜索 625 种精灵形态、579 项战斗技能、242 个特性名称；查看种族值和全部学习来源。保留血脉、等级、阶段与传说条件。
- 在浏览器本机训练两张独立 Q 表，观察训练检查点和固定规则对手评估；可下载模型。
- 用冻结策略比较特性移除、单招禁用、异系倍率中性化，查看实际对局与选择的招式。
- 修改威力和特性参数，运行同环境对照；逐回合核对能量、行动顺序和伤害，导出带口径的实验报告。

## 两个数据范围

| 层 | 当前范围 | 可以回答什么 |
|---|---|---|
| 图鉴资料 | 2026-10-14 BWIKI 快照，625 形态 / 466 图鉴编号、579 技能、242 特性名称（245 内部 ID）、311 技能池、30,921 条学习来源、54 条术语 | 原始机制是什么、谁能学哪些技能、来源条件有哪些 |
| 训练环境 | 独立的 S3 旧快照：6 只精灵、每只固定 4 招、单挑；有 1 组火神水系泡沫候选配招 | RL 与解释性对照流程能否运行；在这些假设下出现了什么行为 |

全量资料尚未接入全量引擎。没有换宠、应对、防御、天气、印记、首领化、随机技能、自动配招搜索、血脉合法性验证或游戏录像校准。统一生命和聚能回复值是实验假设。**页面结果不是玩家胜率、推荐配招或削弱建议。**

微信「洛克广场」因本机控制工具初始化失败，尚未读取；公开资料来自用户提供的 BWIKI。来源与修订号见 [数据说明](docs/data-sources.md)。

## 运行与复现

需要 Node.js 22.12+ 与 pnpm。推荐使用 Node.js 24。

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm test
pnpm build
```

默认访问 http://127.0.0.1:4197/ 。静态构建位于 `dist/`，不需要后端、账号或大模型 API。

```sh
# 保存模型到 public/models
node scripts/train.mjs 42 24000 native
node scripts/train.mjs 137 24000 native
node scripts/train.mjs 43 24000 coverage

# 按报告中的 JSON 配置重跑
node scripts/experiment.mjs experiment.json
```

仓库提供三组真实训练产物，每组 24,000 局。两个种子用于原生配招对照，另一个使用人工指定的补盲配招。不是三次独立统计实验，也没有证明训练收敛。

浏览器草稿只保存在本机。重新载入默认读取种子 42；如需保存本次训练，请先下载模型。

## 为什么这样做

产品目标是帮助策划把“感觉太强”转成可检查的问题，而不是产出一张看似精确的排行。一次实验要说明：谁在什么规则下打、发现了什么行为、可能依赖哪个机制、调整付出了什么代价、哪些反例还没检查。

阅读 [产品与实验设计](docs/product-research.md)、[训练方法](docs/method.md) 和 [机制实现清单](docs/mechanism-backlog.md)。目前没有真实策划访谈或用户测试结果，不把计划写成成果。
