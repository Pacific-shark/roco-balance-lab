# 训练与配队试点：实际跑出了什么

2026-10-16 · 私人面试项目 · 受限模拟器

**本轮跑通了本地 PPO 训练、能力诊断、有限候选筛选、冻结测试、特性移除对照和网页证据展示。** 已观察到策略学习进步；尚不能回答现行游戏中奇丽花的最强配队或正式强度。

工作台的“学习验证”展示全部 23 次实验（22 次完成、1 次达到预算），包含失败记录。按钮“创建实验”仍运行原有轻量流程；新的 PyTorch 训练使用命令行，网页只读其核验后的归档结果。

## 1. 先检查 AI 是否真的在学习

双方使用独立参数，动作包括出招、聚能、换人。PPO 使用实际对战结果更新概率；陪练混合当前策略、历史快照和只读可见信息的规则策略。动作掩码与执行器分别检查合法性。

输入采用保守玩家视角：己方配置、已观测到的对方成员及招式、最后可见状态、合法动作。未公开对方面板、私有配置和下一步指令不进入网络。v3 增加的属性打击关系、己方攻击压力和聚能收益，也仅由该观察计算。它是 provisional 协议，尚未认证为正式游戏的全部信息规则。

| 实验 | 条件 | 种子 42 / 137 / 256 的训练后胜局（每组 32 局） |
| --- | --- | --- |
| v1 | 线性、MLP、实体 GRU；4 套训练构筑；4,096 步；终局奖励 | 三种架构全部 0 / 0 / 0 |
| 延长对照 | MLP；终局奖励；预算耗尽时完成 18,432 步 | 0 / 未运行 / 未运行 |
| v2 | MLP；可见势函数反馈；4 套构筑；32,768 步 | 0 / 1 / 1 |
| v3 | 实体 MLP；32 套构筑；行动描述增强；32,768 步 | 12 / 12 / 14 |
| v3 | 实体 GRU；与上一行相同输入和预算 | 10 / 17 / 21 |
| v4 | 从 v3 实体 MLP 补训聚能残局 | 14 / 未运行 / 未运行 |
| v5 | 从各自 v3 实体 MLP 补训聚能和换人残局 | 16 / 14 / 13 |

v1～v3 均从随机参数开始，初始验证为 0/32。v4、v5 从父模型继续，不能将其“训练前”写成随机模型。v5 每个策略补训 2,048 个单方决策，合计 4,096；基础训练的 32,768 步则是环境同时决策步，两者不直接相加。

这些结果支持“学习有进步”，不支持“GRU 已是最佳架构”：只有三个训练种子，GRU 波动也更大。v2→v3 同时改变了训练构筑、输入和模型，不能将提升单独归功于其中一项。配队试点预先使用 v5 三组实体 MLP；没有在看到测试结果后改选 GRU 的最好种子。

**32 局不是 32 个独立对位。** 验证只有两套留出构筑，通过双方策略、座位、同速方和对手风格组合得到重复评估。三种子的汇总也不能冒充 96 个独立样本，故不展示泛化置信区间。

## 2. 诊断、补训与指标修正

早期模型频繁无效换人或在满能量时聚能。单纯延长训练没有改善留出成绩，因此增加了小型能力题和行为计数，而不是只加训练时间。

可见势函数奖励为 `r' = r + γΦ(next) − Φ(current)`，其中 `Φ` 使用可见双方魔力差和已观察血量损失；终局势值强制为 0，忽略自动重置后的新对局。测试验证折扣求和的消去关系。有限预算、部分可观测和函数逼近下，仍不能据此保证 PPO 学到最优策略。验证胜负只取真实终局，过程奖励不计分。

聚能题经历了两次公开修正：早期对手一直聚能，场下队友血量健康，安全换人也能成立；“两步收尾失败”不能证明不会管理资源。修正后的题让换人会损失最后一点魔力，而聚能后进攻存在获胜路径。随后把真正的终局胜负与两步速度指标分别保存。

v4 只补聚能后，换人题从 47/48 降至 25/48，说明局部优化损伤了其他行为。v5 混合聚能与换人场景，并以正常训练构筑中采集的观察做父策略 KL 保留约束；没有拟合验证或测试观察。

| --- | ---: | ---: |
| 42 | 0/24 | 19/24 |
| 137 | 7/24 | 23/24 |
| 256 | 11/24 | 21/24 |

这里只取未参与补训的槽位排列 3～5，训练使用 0～2。它检验同机制的排列适应，不代表新物种、新机制或真实比赛泛化。终局指标是诊断后的修正，原始两步结果完整保留；不是事先预注册的主指标。

v4 报告曾继承父模型的学习率、环境数等配置元数据。已按实际执行代码修正，并保存原报告和当时源码；模型、胜负与日志未变。该实验用于发现行为退化，没有作为 v5 的父模型。

## 3. 把学习结果接入配队研究

固定奇丽花占一个队伍位置，从受限可执行集合生成 6 套未用于基础训练、验证或测试的六人候选。候选在原型约束内合法，但不代表完整正式服合法性，也没有完成性格、天分和配招最优搜索。

1. 三组 v5 冻结模型分别评估每个候选：6 × 3 × 32 = **576 局筛选**。
2. 根据验证对局得分锁定两套成员有差异的队伍，先保存 ID，再读取测试结果。
3. 两套测试对手构筑上，分别保留和移除目标特性：2 × 3 × 32 × 2 = **384 局对照**。
4. 逐局匹配相同对手、策略、座位、同速方、对手模式和评估种子；确认评估前后参数哈希未变。

合计 **960 局**，耗时约 **53 秒**，训练与评估的大模型 API token 为 **0**。运行依然消耗本机 CPU 与时间；开发对话不包括在这里。

得分为胜 1、达到原型回合上限 0.5、负 0。规则对手与冻结神经对手混合在同一表内；这不是排位赛胜率。两套队伍的平均特性差值均为 0，且符号随种子反转。**目前没有稳定证据把表现归因于奇丽花特性；也不能反过来证明该特性无用。** 冻结策略可能不会利用它，有限对手可能没有触发其价值。

五维评价因此只填入竞技表现和特性敏感度的有限证据；个体贡献需要同定位替换，反制需要技能干预和双方重训，设计一致性需要有来源的设计目标。不会给缺失维度编造分数。

## 4. 目前还没跑通的正式研究条件

- 执行器只有 **10 个形态、42 个技能**。资料库的 631 个形态、824 条技能／特性记录不能当作执行覆盖率。
- 未实现完整当前版本共鸣、首领化及全量技能／特性；固定资料快照不保证等于最新生效数据。
- 尚未实现用户要求的统一 60 级、五星资质、最优天分性格下的全量培养与配招搜索。
- 神经配队试点是有限候选筛选，没有逐队适应训练、多代搜索、同定位替换后重训和全对手反制探索。

正式强度研究入口继续关闭。下一次扩大范围应先核准完整构筑与共鸣结算，再扩展精灵和能力题；不能因为验证得分提高就直接生成排行榜。
