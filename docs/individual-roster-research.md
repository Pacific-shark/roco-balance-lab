# 洛克王国世界：逐精灵研究与角色评价方案 v3

日期：2026-10-15。私人面试项目。本文为待实施设计，不是已完成的训练或精灵强度结论。

最终训练的前置工作以[官方战斗机制核验底稿](official-battle-rules.md)为准。官方描述、模拟器实现、游戏对照三项分别记录；规则核验未通过，不扩大正式训练，也不输出“最优配队”或全环境强度。

## 先找到用法，再评价强度

方案 v3  /  2026.10.15  /  私人面试项目 · 待实施

> 研究问题：在指定版本的完整 6v6 中，一只精灵能以哪些身份进入有效队伍？它实际贡献了什么，哪些对手能反制，强度风险来自哪里？强化学习负责探索打法，产品负责把证据转成可讨论的策划判断。

### 最终交付的三件事

| 交付 | 读者能得到什么 |
| --- | --- |
| 逐精灵研究档案 | 按图鉴编号查看有效定位、最多 3 套有区别的配队、合法培养与配招、适用对手和反制。没有找到有效用法也保留记录。 |
| 可复查的评价 | 对手构成、实际预算、训练种子、对局矩阵、替换实验和关键回放。区分“没学会”“没搜到”和“已观察到作用”。 |
| 可验证的调整建议 | 针对数值、技能分配、补盲或协同提出具体假设；调整后重新探索双方打法，检查是否保留特色、产生新问题。 |

### 已敲定的范围

按编号升序研究各进化分支的最高常规形态；分支和机制不同的形态分别登记，不能按编号大小猜进化终点。研究对象只需占六人队的一席，不要求成为队伍核心。它可以进攻、防守、支援、衔接换人或针对某类对手，也可以兼任多种角色。

研究对象与队友池均采用已核准的最高常规形态；首领化作为对局中的特殊机制核准。固定版本、常规 6v6、60 级、五星成长。天分、性格、配招、槽位顺序、血脉与队伍在合法范围内联合择优；双方条件相同。结论不外推到未纳入的低阶形态或其他赛制。

2026-10-15 补充：[血脉、配招与共鸣修订](bloodline-mechanisms.md)。先固定一个当前血脉，再从符合条件的基础／技能石／该血脉技能中选择四招。整队共鸣位只能装备一个，愿力强化、进化之力、草魔法互斥，次数按本局团队资源记录；外层搜索同时考虑这一选择和首领分支，内层学习有限次数的使用对象与时机。特性生成技能独立处理。来源及共鸣资源检查已实施，具体额度和战斗执行仍待核准。

### 这次优化的重点

新增 AI 能力验收与信息边界；把角色从预设标签改为待验证假设；拆分训练、验证和最终测试；统一编号之间的预算与对手；明确停止规则、失败状态和先试点后批量的实施顺序。

本文件是方案更新。现有原型仅覆盖 10 个可执行形态、42 个技能，不能代表全图鉴；本轮不启动训练，也不生成精灵排名。

## 先过数据和规则关

01 / 通过的是明确范围，不能用“小样本通过”代替全环境认证

建立版本清单：玩法、生效日期、来源修订与哈希、公告覆盖区间、最高常规形态及排除原因、技能与特性实现映射、对照样本和未解决冲突。每次运行绑定清单；更新数值、技能池或机制后，新旧成绩分开保存。

| 准入项 | 需要补齐的内容 | 通过标准 |
| --- | --- | --- |
| 当前有效数据 | 从可信基线到目标版本的调整、热修与学习面变化；逐字段解决来源冲突。 | 抓取日期不代替生效版本；影响结论的差异全部关闭。 |
| 合法配置 | 模式准入、分支形态、技能获得与共存、重复与空栏例外、血脉、天分、整队限制。 | 生成器和校验器均拒绝非法配置；未知条件显式阻塞。 |
| 面板与伤害 | 当前版本实机样本；生命增减性格、资质边界、取整、攻防与减伤等。 | 确定性样例逐值一致；不同来源和边界分别有证据。 |
| 事件结算 | 出手、换人、后台、力竭、复活、魔力、回合末、首领化及关键交互。 | 逐事件回放对齐；范围内效果都有处理，关键用例全部通过。 |
| 随机与信息 | 核准随机集合、分布和公开时点；区分完整状态与双方可见状态。 | 未知分布不默认均匀；隐藏配置与未来事件不泄漏。 |

### 覆盖率要有分母

分别公布：范围内合法形态数、必需技能／特性数、已实现数、已有实机对照数及关键交互通过数。首领化、动态变招和随机获取技能涉及的依赖要递归展开；不能只检查初始携带的四个技能。研究对象核准后，队友与对手仍需同样核准。

### 当前面板证据的边界

现有 60 级五星音速犬公测视频样例六维对齐，已用于修正性格正增益与分步取整；不能证明当前赛季所有面板规则。正式训练前仍补现版本样本、生命性格和取整边界。公式依据与样本保留在项目证据文件，不在本方案中重复宣称“全部真实”。

> 小范围试点只验证流程。完整目标范围未通过时，所有试点结果必须显示排除项，不能解释成真实全环境强度。未支持的机制阻塞相关配置，不能悄悄变成“无效果”。

## 先证明 AI 会玩，再让它评价

02 / 避免把学习能力不足误判成精灵太弱

| 信息类别 | 方案要求 |
| --- | --- |
| 己方与公开信息 | 只输入目标玩法实际可见的己方配置、公开状态和对局记录；具体字段先用游戏画面核准。 |
| 对方已揭示信息 | 记录何时、因何事件揭示；保留历史供策略推断，不能提前读取尚未公开的配置。 |
| 未知与禁止输入 | 未揭示内容标为未知；禁止读取对方本回合已提交指令、未来随机结果和未来状态。 |
| 隔离验收 | 构造公开历史相同、隐藏状态不同的两局：观察值必须一致，固定策略与随机流下决策也应一致。合法动作掩码不得绕道泄漏隐藏信息。 |

训练环境持有完整状态用于结算和事后审计；第一版策略与价值估计均使用玩家可见信息及历史。现有原型公开双方全部配置，只能继续作为受限原型，不能直接当作目标玩法的信息模型。

### 建立能力题库，覆盖不同角色的价值

| 能力 | 场景与验收证据 |
| --- | --- |
| 资源与出手 | 能量不足、聚能与进攻取舍；不能只看立即伤害，检查合法行为和后续兑现。 |
| 轮转与反制 | 安全换入、被克制时应对、强制换人与补位；检查换入成本和后续行动。 |
| 支援与延迟收益 | 当前回合让出输出，换来队友后续收益；记录收益链及对团队结果的影响。 |
| 后台与机制记忆 | 后台效果、冷却、已公开技能与跨回合条件；不能只依赖当前在场面板。 |
| 不同对手的适应 | 对规则基线、历史策略和不同体系分别检查，避免只会打当前陪练。 |

每类至少准备正例、机会成本反例和组合场景；动作不唯一时接受合理动作集合或已核准的结果约束。用规则推演、专家复核和真实回放标注题目，不把某个脚本的选择直接当作真理。

> 能力门槛：关键规则与信息隔离检查全部通过，相关角色的能力题达到预先登记的标准，再做个体评价。持续输给基础策略或无法兑现该角色收益时，标记“策略能力不足”；两个 AI 彼此胜率接近 50% 不能证明它们足够强。

## 按编号推进，队伍与打法交替探索

03 / 固定研究对象的一席，放开它在队伍中的身份

| 步骤 | 执行内容 | 留下的证据 |
| --- | --- | --- |
| 1  建档 | 读取形态、特性、合法学习面与限制；提若干角色假设，同时保留无角色预设的探索分支。 | 来源、准入结果、角色假设及反例。 |
| 2  生成队伍 | 固定研究对象；搜索其他五位及全队合法培养、技能与槽位。允许它服务于其他主力。 | 完整配置、来源与配置唯一标识。 |
| 3  学习操作 | 两个独立策略进行完整 6v6；混合当前对手、历史策略、规则与训练专用实战基准。 | 参数更新、训练回报、能力题表现、快照。 |
| 4  筛选再探索 | 在验证池筛选和改变构筑；新构筑获得适应预算，再做下一轮，避免只按旧策略评价新配招。 | 候选谱系、筛选依据、适应成本。 |
| 5  保留不同用法 | 最多留 3 套：综合搭档、资源循环、胜利方式与对位差异判断；不足则少报。 | 各套队伍承担的角色与差异。 |
| 6  冻结并复验 | 配置和策略冻结后进入统一测试；再安排独立的替换／机制实验。 | 对局矩阵、有效样本、失败记录。 |

### 角色是观察结果，不能锁死搜索空间

先用技能机制提出支援、进攻等假设，为冷启动提供入口；同时保留自由组合的候选，避免只搜“大家已经知道的用法”。根据多局行为、资源流与替换结果归纳实际角色。角色标签允许重叠，同一精灵可在不同构筑中承担不同任务。

### 策略要可迁移，也要能证明真的学过

拟从带对局历史的通用策略开始验证，两个 AI 使用独立参数与更新记录，共享同一份冻结的基础初始化。现有线性策略保留为基线；是否更换算法，以能力题、训练稳定性和实际算力测试决定。保存训练前后模型标识、更新次数、独立种子与对照成绩，避免将手写规则包装成学习成果。

主要训练目标是团队胜负，不奖励研究对象的伤害或出场率来强造重要性。若为学习效率添加过程奖励，需单独记录并与不加奖励的版本对照，检查是否诱导无效回复、无限换人或牺牲长期收益。

> 报告统一写“本版本与本预算内发现的优势配队”。不能因为候选少、训练没跟上或某个种子失败，就宣布全局最优或判定精灵没有价值。

## 让不同编号的结果可以比较

04 / 训练环境可以发展，最终评价口径必须一致

| 数据用途 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| 训练池 | 更新策略；逐轮纳入历史对手和新发现构筑。 | 用训练内成绩充当独立测试结果。 |
| 验证池 | 筛选队伍、调参、决定追加预算和提前停止。 | 被反复查看后还称为“从未见过”。 |
| 冻结测试池 | 最终一次性评价已锁定的配置、策略与方法。 | 按测试输赢挑队、调权重，再复用为独立证据。 |

### 统一对手，保留循环克制

测试池按体系和打法分组；先公布各组成绩，再给汇总。首版各预设体系等权，组内不同配置／策略按预登记规则分配权重；近重复对手去重，不能靠多塞某类弱队抬分。没有真实出场分布，就不叫“天梯胜率”。若分组口径改变，所有对象一起重算。

编号只决定排队顺序。每轮固定训练池版本和基础初始化；新对手进入下一轮。所有编号最终用同一冻结池复评，同时展示体系间的对局矩阵。发现循环克制时保留对位解释，不硬排成一条绝对强弱链。

### 同预算与独立性要一起记录

每个对象使用相同候选探索额度、环境决策步数和独立训练种子安排，记录实际计算时间与有效对局。后研究对象不能直接继承额外训练的模型后与早期成绩混排；可共享冻结基础模型与无泄漏缓存，新增学习成本单列。

初步试点采用 3 个独立训练种子检查明显分歧；正式报告暂按至少 5 个种子规划，算力基准后冻结。种子数量是工程起点，不保证统计可靠。冻结策略后交换左右身份；随机重复按已核准的机制采样。完全确定、完全相同的重放不能重复计为独立样本。

### 结果怎么统计

胜率 = 胜场 / 有效终局数；平局率单列。若另用得分率，则明确为（胜场＋0.5×平局）/ 有效终局数。错误与未按真实规则结束的超时单列，不随意算平局或隐藏删除；失败集中于某体系时暂停该比较。

汇总按预设体系权重计算，不按总对局数量倒推权重。对手配置、训练种子和随机重复分层保存；不把同一策略的大量重复局当成大量独立模型。样本不足只报分布和范围，满足条件后才给区间及计算方法；不能只挑最高分种子。

## 个体价值要放回它的角色里

05 / 评价单位：精灵 × 角色 × 队伍体系 × 对手环境

| 维度 | 记录与解释 | 不这样下结论 |
| --- | --- | --- |
| 条件强度 | 各套队伍对统一环境的成绩、差异与最难对位。 | 最高一次胜率 = 稳定强度上限。 |
| 实际贡献 | 有效资源、关键行动、后台作用；同角色替换和再优化。 | 队伍赢了 = 每个队员都很强。 |
| 角色适配 | 进攻能否突破；防守能否化解威胁；支援能否创造可兑现的收益。 | 所有精灵按输出或出场次数排名。 |
| 配队适应 | 不同搭档和打法的有效范围，对某个伙伴或环境的依赖。 | 多个近似队伍 = 高泛用性。 |
| 特色兑现 | 特性／技能是否改变配招、操作、资源链与分工。 | 高触发频次或高伤害 = 有特色。 |
| 反制与代价 | 对手是否有可执行的应对；槽位、能量、时机和魔力成本。 | 平均胜率高 = 必须削弱。 |

### 贡献记录要追到实际受益

每个收益事件保留发起者、效果所有者、技能／特性来源、受益者、理论值、实际增量和溢出。能量统计只把实际增加记为有效回能；是否让关键技能更早使用，还要看时间链与对照局。回复、护盾、减伤和承伤避免重复记账。

对进攻角色观察突破与收割；对防守角色观察关键威胁化解与队友存活机会；对支援角色观察有效供给与后续兑现；对换人衔接观察安全入场和创造的行动；对针对性角色观察特定劣势对位的改善。指标解释角色，不直接合成跨角色总分。

### 未出场，也不能自动判无用

后台收益或保留威胁可能影响对手选择，但“威慑”不能凭想象补。需通过动作分布、替换实验和回放找到证据；看不到实际收益且无对照支持时，标记“贡献证据不足”。不同角色可以并存，角色多也不自动加分。

> 奇丽花可作为支援能力的检查案例：自身回能与富养化的队友回能分开记，比较实际受益、行动机会成本及后续技能链。这里只规定怎样检验，不预填它的最优队伍、真实定位或强度结论。

## 解释风险，再验证调整

06 / 让“太强了”变成可以复查的设计问题

| 实验 | 控制什么 | 能够解释什么 |
| --- | --- | --- |
| 同角色替换 | 选功能相近的合法候选；保留六人规则。先固定其他位置，再给双方同预算重新配队与训练。 | 依赖当前队友的程度，以及更充分适应后是否仍有优势。 |
| 单项机制调整 | 分别改特性参数、技能收益／能耗、补盲来源等，完整记录变更。 | 当前打法依赖哪段机制；适应后影响是否保留。 |
| 关键协同对照 | 先做单因素，再对怀疑的技能×队友或补盲×强化组合做联合实验。 | 是否是组合带来的额外优势；避免把几个差值相加当贡献。 |
| 寻找可行反制 | 在验证环境中给对手相同预算探索应对，再对未用于调试的场景复核。 | 已找到什么应对、代价多高；没找到不等于不存在。 |

### 固定打法和重新适应，回答不同问题

固定配置／策略的实验衡量“现有打法依赖它多少”；重新搜索、训练衡量“改变后还能找到什么打法”。两者分别报告。机制删改必须保持实验规则自洽；临时实验配置明确标为假想规则，不能混入真实合法构筑。

### 提出调整前，核对四条证据

① 优势跨多个相关对手与种子重复出现；② 收益能追到具体技能、补盲或协同；③ 已检查机会成本与可行反制；④ 排除明显规则错误、信息泄漏和学习不足。证据不齐时只列研究假设。即使齐全，也是在模拟环境内支持风险判断。

若确有风险，优先比较几个小幅、可解释的改动，而不是直接删除特色。调整后双方重搜重训，统一检查原本弱势对位、其他受影响精灵与新优势组合；记录“降低压制、保留玩法、产生副作用”的取舍。

### 设计意图与体验判断分开写

“符合最初设计理念”必须对应官方说明或访谈。没有来源，只能写“依据机制提出的定位假设”。策略多样性、反制窗口等可作为体验线索，但是否有趣仍需玩家试用与专家复核。访谈和评审尚未开展时，报告如实标注。

> 每条建议附：现象、证据局、候选原因、替代解释、拟改动、预期影响、复验结果与限制。不能把多个消融差值加成“总贡献百分比”，也不设缺乏校准的综合强度分。

## 让程序自主跑，也知道何时停

07 / 不在训练循环里调用大模型；用记录和门槛控制成本

### 先测速，再冻结预算

先用已核准场景测每秒环境决策数、峰值内存、完整对局长度和不同机制开销。按可用硬件设置候选额度、环境步数、单任务时限、日志上限与检查点间隔；把实际取值写入运行清单后才开始实验。此时不承诺未经测量的“几小时跑完全图鉴”。

| 情况 | 处理与停止条件 |
| --- | --- |
| 效果稳定 | 在固定验证集上，连续 3 个检查点没有超过预登记的最小有意义提升，且关键能力、对位与种子差异达到门槛，可停止该轮搜索。阈值在试点后冻结；不称数学收敛。 |
| 预算耗尽 | 保留已发现的构筑和不确定性，按“本预算内结果”结束；未稳定时不得转成弱精灵结论。 |
| 值得追加 | 学习仍明显改善、不同种子分歧大，或相关角色能力未通过：按事先规定的额度追加，结果与同预算首轮分列。 |
| 异常或阻塞 | 规则不支持、非法构筑、非有限数值、无法解释的事件、信息泄漏：保存最小复现并暂停相关任务，不反复自动重试。 |

### 复用可以省算力，不能改变比较口径

共享冻结基础模型，缓存同版本下合法配置与已确认的确定性结算；缓存键包含版本、完整状态与必要随机状态。队伍可跨精灵复用并保留来源，但测试资料不进入训练缓存。热启动的训练来源、累计预算及额外适应成本必须可查。

保存编号与配置标识、代码／数据／规则版本、完整随机状态、模型与优化器状态、对手池版本、候选队列和实际预算。恢复前校验一致性；版本改变时开新实验。相同输入重放应能得到相同记录。

### 把研究结论和任务状态分开

任务状态：待核对 → 规则可运行 → 搜索中 → 待独立评估 → 有限结论；另有规则阻塞、策略能力不足、探索不足。研究结论可以是稳定功能位、体系依赖、针对性选择、贡献不明或本预算内未发现有效用法，不能用一个“失败”混在一起。

> 训练、搜索、常规统计和阈值监控由本地程序完成，不逐回合请求 GPT。大模型只用于前期实现、异常诊断和阶段解释；程序定期写摘要，保存关键回放，避免持续读取整份日志。

## 产品页面要让判断有据可查

08 / 面向战斗策划与研究者，先支持判断，再考虑扩展功能

| 页面 | 核心内容 | 对应决策 |
| --- | --- | --- |
| 研究总览 | 按编号查看准入、角色、研究阶段、证据缺口；统计所有任务，包括失败与未完成。 | 现在覆盖了谁，哪些结果可以读。 |
| 精灵档案 | 定位结论在前；分队伍展示培养、配招与理由、个体任务、优势对位、反制和限制。 | 什么时候值得带它，代价是什么。 |
| 证据对照 | 原方案／替换／机制调整并排；关键回合、资源链、对局矩阵和实验配置可展开。 | 优势是不是它造成，原因在哪里。 |
| 调整实验 | 记录问题假设、改动、双方适应预算和统一复评结果；可回看旧版本。 | 是否值得改，是否伤及特色。 |

### 一份个体报告的固定结构

先给一句有条件的结论，例如“在某类体系中承担资源支援，对某类对手稳定有效”；随后列角色证据与最多 3 套不同配队，再给对位、反制、替换结果、机制原因和未解决问题。首页同时显示适用版本、评估范围、预算和证据状态，避免脱离条件转发。示例句是模板，不是任何精灵的实测结论。

### 产品效果也需要验收

邀请 3—5 位熟悉对战的玩家做首轮可用性检查：找出一只精灵的有效定位、说清配队理由、找到反制、追到一条判断的证据，并指出哪些地方还不能信。记录任务完成情况、误解、耗时与反馈。人数是形成性测试的起点，不代表玩家总体结论。

项目价值看能否帮助人作出有依据的判断：来源能否追溯、错误能否定位、结论能否复现、调整是否有完整前后对照。覆盖数和训练局数只描述进度；不以“训练了很多局”代替质量。

### 面试展示先做一条完整证据链

从一个真实机制疑问出发，展示规则核查、角色假设、搜索过程、失败案例、独立评价和调整复验。重点说明为什么这样定义问题、如何避免误判、如何在有限算力下取舍；只把已经实现和验证的部分写成成果。

> 项目继续私人保存。首轮交付聚焦完整研究闭环与几份可审查的报告；不先做公开排行榜、社区平台或没有依据的花哨总分。

## 先试点，再按编号扩展

09 / 每一阶段都有产物与准入条件

| 阶段 | 产物 | 进入下一阶段的条件 |
| --- | --- | --- |
| A  核准范围 | 最高常规形态清单、分支／首领化表、版本账、合法性规则、面板与事件样例。 | 试点涉及的队友、对手、动态技能等依赖全部核准；范围外明确排除。 |
| B  验收策略 | 可见信息协议、能力题库、规则基线、训练前后对照与硬件测速。 | 关键规则和信息隔离通过；试点所需能力达标，预算参数已登记。 |
| C  小范围闭环 | 首批 4—6 个对象，覆盖进攻、支援、防守、轮转等不同假设；其中包含奇丽花。 | 每个对象完整经历配队、学习、独立测试与归因；角色是待检验假设。 |
| D  批量研究 | 按编号队列运行，所有对象都有状态；失败可定位、暂停可恢复。 | 完整目标范围通过准入；试点反映的方法问题已修正并冻结。 |
| E  同环境复评 | 统一冻结池上的个体报告、对局矩阵、风险与调整实验。 | 全部采用相同口径；未完成对象保留，不将缺失对象排到榜尾。 |

试点对象以资料完整度和机制差异选择，不按先验强弱挑“容易出成绩”的精灵；正式批量仍按图鉴编号推进。其他具体对象待合法清单核准后确定，不虚构某只精灵的定位。
