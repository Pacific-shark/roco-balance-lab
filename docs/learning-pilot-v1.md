# 深度强化学习试点：先证明策略在学，再研究精灵

2026-10-16 · 第一阶段 · 受限原型

本阶段把上轮模型选型落实为可执行对照：线性策略、MLP、实体编码＋GRU 使用同一份玩家视角输入、合法动作集合、训练预算和评估场景。目标是检查算法实现与观察隔离，初步观察训练收益；不评价现行游戏精灵强度。

## 已实现的训练链路

Python/PyTorch 负责模型、PPO 更新和实验记录，Node.js 负责批量调用现有模拟器。双方动作全部提交后才结算；不重新实现第二套战斗规则。子进程使用管道通信，Windows 下隐藏运行，不启动网页、游戏或视频。

| 部分 | 当前实现 |
| --- | --- |
| 信息输入 | 复用保守观察协议；未见对方成员、未公开招式与私有面板不进入网络；已见场下成员保留最后观测值 |
| 动作 | 4 个技能槽、聚能、6 个换人槽、等待，共 12 个位置；策略概率和执行器双重检查合法性 |
| 模型 | 线性 Actor-Critic、两层 64 宽 MLP、共享实体编码器＋64 维 GRU＋行动条件打分 |
| 学习 | 两个独立参数策略；PPO clipped objective、价值损失、熵奖励、GAE、梯度裁剪 |
| 记忆 | 跨回合保留，新对局重置；按完整时间序列更新，不随机打乱回合 |
| 自博弈 | 当前策略、可见信息规则对手、持续保存的历史快照；每局确定陪练，不中途换陪练 |
| 记录 | 初始／最终参数哈希、配置、代码与环境哈希、梯度及损失、对手构成、逐局验证结果 |

三个架构都由 PPO 训练。这里的 `linear` 是新建的同信息、同算法线性对照，不是旧版读取完整状态的线性策略梯度。现有旧模型不参与这张成绩表。

实体模型为每只精灵使用相同编码器，分别汇总己方、对方及在场成员，再处理对局历史。行动描述携带当前技能或换入对象的信息，保留动作与成员的对应。未知精灵没有伪造面板；网络也不读取模拟器预测的对方实际伤害。共享编码不意味着已经证明对未见物种的泛化能力。

当前观察输入包含 12×104 维精灵字段、24 维全局字段、12×178 维动作描述和合法动作掩码。确切字段随报告保存。游戏实际公开哪些字段仍需核准，因此名称保留 `provisional`，不能称为已复现真实 PVP 信息条件。

## 奖励与更新

终局胜利 +1、失败 −1；不额外奖励研究对象伤害、出场次数或换人。此版不使用隐藏状态计算过程奖励。原型引擎达到 100 回合上限时终止，训练回报为 0，报告单列 `roundCaps`，不把它描述成游戏自然平局。

PPO 参数：学习率 3e−4，GAE γ=0.99、λ=0.95，裁剪范围 0.2，熵系数 0.01，价值损失系数 0.5，梯度范数上限 0.5。每 32 个向量步收集一次，按环境拆分序列做 3 轮小批量更新。GRU 使用采集时的起始隐状态做截断反向传播；没有重算完整历史或加入 burn-in，此项近似需要后续比较。

第一次没有历史快照时，相应陪练抽样落到规则策略；之后每两次更新保存两方快照，最多保留 8 个。已有对局继续使用它开局抽到的快照。报告记录实际对手决策数量，不用设定概率冒充实际样本占比。

## 对比协议

- 固定 4 套原型训练队伍；用与训练种子无关的固定种子生成 2 套验证构筑和 2 套测试构筑，完整配置去重。
- 第一轮每个架构使用 42、137、256 三个种子，各 4,096 个环境决策步。一次环境步包含双方同时决策；实际参与学习的单方决策数另记。
- 每次训练前、后均在相同验证场景各打 32 局，交换策略、座位、同速方和规则对手风格；评估采用随机策略，固定独立评估种子。
- 验证对手仅为两个构筑上的简单可见信息脚本，重复座位不等于独立对位。测试集不用于本轮筛选或展示成绩。
- 同时报告胜、负、回合上限、平均回报与训练前后差值。不能只挑最好种子，也不能以参数变化证明会玩。

新构筑与物种泛化、支援和轮转能力题、更强的冻结对手池，以及可复查的实际对局，目前没有完成。架构与输入表示同时发生变化，因此本轮即使 GRU 领先，也不能把差异全部归因于记忆；后续应加入实体编码但不带 GRU 的消融对照。

## 运行

使用 Python 3.12 与 Node.js 24+。依赖安装在项目独立环境；不修改 Codex 的 Python 环境。

```powershell
python -m venv .venv-rl
.venv-rl/Scripts/python.exe -m pip install torch==2.14.1+cpu --index-url https://download.pytorch.org/whl/cpu
.venv-rl/Scripts/python.exe -m pip install numpy==2.3.4

# Node 已加入 PATH 时无需设置；否则填写本机实际路径。
# $env:ROCO_NODE = '你的 Node 可执行文件路径'

.venv-rl/Scripts/python.exe -m learning.train --models linear mlp entity_gru --seeds 42 137 256 --steps 4096 --envs 4 --max-seconds 120 --threads 1 --output .local/my-pilot
```

`--max-seconds` 为每个架构、每个种子的累计时限，含训练前后评估；预算检查位于环境步与更新边界，单次更新可能有少量超时，管道另有响应超时。默认 1 个 CPU 线程，最多允许 4 个。全程无大模型调用。

`.local/my-pilot/summary.json` 汇总全部运行；子目录中的 `report.json` 保留证据，`model.pt` 保存模型与优化器。文件不上传 GitHub；重复输出目录会拒绝覆盖。模型检查点可供后续加载评估，本阶段未实现包含正在进行的对局、随机状态和历史池的完整断点续训。

检查命令：

```powershell
node --test --test-isolation=none test/learning-bridge.test.mjs
.venv-rl/Scripts/python.exe -m unittest discover -s test -p learning_test.py -v
```

## 下一阶段的决定依据

### 第一轮实际结果（2026-10-16）

9 次运行均完成，每次 4,096 个环境决策步，合计 36,864 步、822 局训练对局。训练前后各执行 288 局验证，共 576 局；各次运行用时合计约 200 秒，使用 CPU、单线程，不调用大模型 API。

| 架构 | 每个策略参数量 | 训练前胜局／验证局 | 训练后胜局／验证局 | 平均回报变化 |
| --- | ---: | ---: | ---: | ---: |
| 线性 | 44,317 | 0 / 96 | 0 / 96 | 0 |
| MLP | 223,181 | 0 / 96 | 0 / 96 | 0 |
| 实体编码＋GRU | 69,506 | 0 / 96 | 0 / 96 | 0 |

所有验证局均以失败结束，没有回合上限终止。这里的 96 局是三个种子各 32 局的汇总，不能当作 96 个独立对位来计算泛化置信区间。

每次运行的两个策略参数均发生变化，完成 32 次采集与更新，实际用到了历史对手，记录的梯度和损失均为有限值。这只能支持“训练链路可执行”，不能支持“策略已学会对战”或“深度模型优于线性模型”。本轮没有观察到验证胜率提升，因此不选最佳架构、不启动配队排名，也不追加长训练来追求好看的结果。

终局奖励稀疏、预算较短、行动探索低效等都可能影响表现，但目前没有逐项实验来确定原因。下一步先做可解的小型能力题，检查学习到的出招、聚能与换人行为，再决定是否增加预算、引入课程学习或加入记忆消融。

全部种子的配置、更新日志与逐局验证记录见 [实验摘要](evidence/deep-rl-pilot-v1/summary.json) 及同目录的 9 份报告。模型权重与原始运行目录保留本地；摘要是从实际文件提取的结果，不是示例数据。

先补机制与信息核验、能力题、训练曲线和有代表性的对手，再决定是否追加训练预算或模型复杂度。通过后才接入约束配队搜索与 MAP-Elites；LightGBM 辅助筛选和 PSRO 仍属于后续方案。现有前端继续展示 v0.4 工作台，尚未提供新 PyTorch 训练器的启动按钮。

算法参考：[PPO](https://arxiv.org/abs/1707.06347)、[Deep Sets](https://arxiv.org/abs/1703.06114)。以上结构、超参数和预算是本项目的试点选择，不是论文针对本游戏验证过的推荐配置。
