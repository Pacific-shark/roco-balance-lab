## 2026-10-18 实现进度

研究范围仍是 **3 个测试目标，259 个最高常规形态候选作为队友和对手来源**。没有把未实现的精灵从研究范围中删除。259 是资料候选数，当前排位合法性尚未逐项认证。

新增的 `src/battle-programs.mjs` 将固定版本的完整技能／特性说明转换为操作；只识别到半句时整条拒绝执行。`src/battle-kernel.mjs` 负责实际结算，目前仅接受机制测试用途，尚未接入 PPO。历史 10 形态／42 技能的学习环境和检查点保持原状。

已接入的共用逻辑包括能量与实际回复、多段攻击、应对打断、中毒／灼烧／冻结／引电、部分印记和天气、永久技能成长、按状态层数计算效果、上回合历史条件、禁足、技能脱离、返场、迅捷及选择分支。技能脱离会暂停回合让对应一方选择替补；剩余攻击作用于入场精灵，已离场者的原指令不会转移给替补。离场支援效果记录原特性来源，替补仍保留自己的特性。上述为程序实现与回归结果，事件顺序和保留条件仍需游戏样例校准。

发现并修正了序列化后 `-0` 变为 `0` 导致的账本差异；延迟效果保存槽位标识而非对象引用。先手特性与扇风的加成沿用已有的同区间相加规则，避免新执行器与已有公式样例不一致。

下一批优先处理动态改招／传动、萌化／变形、蓄力与附加伤害，再接共鸣和首领化。还需要完成全量观察／行动接口、配队配招培养联合搜索，以及现行模式和结算校准。**这次没有启动用户要求的全量配队强化学习，也没有新增该试点的模型权重。** 现有测试套件中原有的小范围算法回归不算这项新训练。

完整检查为 118 项 JavaScript 测试、36 项 Python 测试通过。可复查：[覆盖与未解析原文](evidence/full-roster-mechanism-build.json) · [执行记录与代码校验值](evidence/kernel-verification-2026-10-18.json)。以下命令均为本地检查，不调用模型 API；开发对话与 CPU 时间不包含在运行时的“0 API token”中。
