## 2026-10-19：把周报案例接到执行器

已修正新执行器的血脉技能筛选：构筑用数字编号，原始学习表用中文名称，旧代码直接比较两者，漏掉了所有只有血脉来源的技能。现在先按 Config 映射名称，再合并基础、技能石和当前血脉来源；不会因此允许跨血脉配招。新增检查覆盖 259 个候选的 19 个常规／首领血脉分支，共 4921 次来源集合核对；特殊血脉仍明确拒绝。这是来源一致性验证，不是当前排位准入认证。

新增贮藏的执行与过程记录。机制样例让水灵实际使用三次水系技能，再让彩蝶鲨入场：其四招“贮藏／天洪／针状物／寒风吹”在程序中的携带能耗为 0／4／0／0，贮藏因此给双攻各增加 200%；无铺垫对照为各增加 50%。样例保留双方完整被动，使用六人机制测试场景，但其他位置是测试辅助配置，**不是对时报完整电环水队的复刻或胜率实验**。

贮藏按当前携带能耗计数，包括自身技能槽；包含常驻减耗、技能自身永久修正、印记与光环，暂不纳入仅在本次使用生效的折扣或未选择分支。该区别及取样时点仍须游戏对局核对，不把单元测试写成实机认证。当前来源文字见 [BWIKI 贮藏](https://wiki.biligame.com/nrc/贮藏（物品）)，水系累计与入场减耗来自彩蝶鲨特性；“携带能耗”和本次结算费用分开实现，日志保留用于复查的四槽能耗。

133 项 JavaScript 测试通过，其中新增 6 项覆盖血脉漏招、合法／非法配招、贮藏前后对照、实际水系行动链、当前能耗边界和存档恢复。80 场机制回归完成，4977 次决策、854 次存档恢复对比一致。没有运行新训练。执行器与规则版本升级为 2，旧实验继续按其历史版本解读。

当前必需技能覆盖为 **347 / 579**，特性为 **75 / 207**，游戏逐事件对照仍为 0。第一套电环水队中五种特性已有程序实现，火羽的“不死鸟”仍缺；已经核对的五条技能来源可接入，但完整 24 招、培养、血脉和共鸣配置尚未录齐。后续按 [逐队缺项清单](evidence/pvp-study-prerequisites.json)推进，不能因为已知的五招通过就误称完整队伍可训练。[本轮验证记录](evidence/pvp-baseline-verification-2026-10-19.json)

复查命令：`node --test --test-isolation=none test/pvp-baseline.test.mjs`；更新缺项清单：`node scripts/audit-pvp-study.mjs`。这两项均为本地运行，不调用模型 API。

## 2026-10-18 实现进度

研究范围仍是 **3 个测试目标，259 个最高常规形态候选作为队友和对手来源**。没有把未实现的精灵从研究范围中删除。259 是资料候选数，当前排位合法性尚未逐项认证。

新增的 `src/battle-programs.mjs` 将固定版本的完整技能／特性说明转换为操作；只识别到半句时整条拒绝执行。`src/battle-kernel.mjs` 负责实际结算，现接受机制测试与明确标记的受限训练，完整图鉴研究入口仍关闭。历史 10 形态／42 技能的学习环境和检查点保持原状。

| 核对项 | 当前结果 | 数字的含义 |
| --- | --- | --- |
| 必需技能 | 346 / 579 已解析并接入执行器 | 仍缺 233 条；不是 346 条游戏实测通过 |
| 必需特性 | 75 / 207 已解析并接入执行器 | 保留精灵自身特性，仍缺 132 条 |
| 完整依赖 | 0 / 259 形态的全部来源技能池完成 | 能装备四个已实现技能，不代表全部玩法已覆盖 |

| 游戏逐事件对照 | 0 个 | 正式强度结论仍不具备依据 |

已接入的共用逻辑包括能量与实际回复、多段攻击、应对打断、中毒／灼烧／冻结／引电、部分印记和天气、永久技能成长、按状态层数计算效果、上回合历史条件、禁足、技能脱离、返场、迅捷及选择分支。技能脱离会暂停回合让对应一方选择替补；剩余攻击作用于入场精灵，已离场者的原指令不会转移给替补。离场支援效果记录原特性来源，替补仍保留自己的特性。上述为程序实现与回归结果，事件顺序和保留条件仍需游戏样例校准。

后续受限 PPO 评估暴露了聚盐的频次错误：状态技能的全部效果被按连击数重复执行，使“使用后永久连击数 +1”错误地随每一段增加。已区分逐段效果与每次使用效果，回归验证连续三次使用为 2／3／4 连击；错误版本的学习成绩不作为结论，修正后重新训练。回放输出增加大小限制，活动统计独立遍历完整事件流。

发现并修正了序列化后 `-0` 变为 `0` 导致的账本差异；延迟效果保存槽位标识而非对象引用。先手特性与扇风的加成沿用已有的同区间相加规则，避免新执行器与已有公式样例不一致。

下一批优先处理动态改招／传动、萌化／变形、蓄力与附加伤害，再接共鸣和首领化。还需要完成全量观察／行动接口、配队配招培养联合搜索，以及现行模式和结算校准。**全量配队强化学习仍未启动。** 用户随后要求先看运行结果，已新增 `experimental-training` / `supported-builds-incomplete-rules` 的独立试验范围；107 个可执行形态可参与配队，保留原有特性，不能据此视为 259 个来源候选已全部可训练。具体模型与配队结果见[训练报告](kernel-ppo-results-2026-10-18.md)。

机制补齐阶段通过 118 项 JavaScript 测试、36 项 Python 测试；后续加入训练适配、聚盐与同图鉴编号排重回归后，127 项 JavaScript 测试及 3 项新 Python 适配器检查通过，80 场机制回归再次通过。可复查：[覆盖与未解析原文](evidence/full-roster-mechanism-build.json) · [前一阶段执行记录](evidence/kernel-verification-2026-10-18.json) · [本轮训练与核验](kernel-ppo-results-2026-10-18.md)。以下命令均为本地检查，不调用模型 API；开发对话与 CPU 时间不包含在运行时的“0 API token”中。

```sh
node --test --test-isolation=none test/battle-kernel.test.mjs

```

最后一条当前应以代码 2 拒绝完整图鉴研究，并列出缺口；不能把缩小后的试验池标记为通过全量核验。受限试验使用不同的范围标识，不改变这项检查。连续执行报告保存在 `.local/kernel-build/regression.json`，固定种子 20261018，可重复运行。
